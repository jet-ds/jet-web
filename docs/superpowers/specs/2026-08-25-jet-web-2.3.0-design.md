# Jet Web 2.3.0 Design

**Status:** Approved; implementation plan ready

**Date:** 2026-08-25; amended 2026-08-26

**Release target:** `2.3.0`

**Implementation plan:** [`docs/superpowers/plans/2026-08-25-jet-web-2.3.0.md`](../plans/2026-08-25-jet-web-2.3.0.md)

## Executive decision

Jet Web `2.3.0` will make the site's public collections easier to discover and quieter to read, while making the underlying design and verification systems more intentional. Blog becomes search-first. Works remains category-filtered and becomes strictly chronological. Homepage Blog and Works previews become high-fidelity, manually looping depth carousels over finite server-resolved collections. Both hubs use one coherent collection-card anatomy. Tags remain useful metadata without dominating public presentation.

The release also corrects adjacent product boundaries that the collection work exposes: Egregore renders constrained Markdown without weakening citation provenance; long-form article navigation becomes sticky and available on mobile; prose links gain a legible content-specific accent treatment; and the test suite is revalidated and aggressively compacted at the browser boundary.

The approved pre-RC amendment completes the public-information boundary around those changes. It adds route-derived structured-data qualification, a build-generated `llms.txt`, production-only analytics with an explicit developer-device opt-out, a visible Digital Squad affiliation linked to `Person.worksFor`, and the final approved Blog content. It also revises the Homepage carousel from a separate media-and-companion composition into a larger image-led card whose metadata disclosure is deliberate on hover/focus and stable on touch devices.

Before those surface changes, `2.3.0` completes the Tailwind CSS 4 migration by moving theme ownership out of the compatibility JavaScript configuration and into CSS-first `@theme` declarations. A fresh dependency and security audit refreshes the exact lockfile, adopts compatible current updates, and records explicit exclusions. The platform work is part of this release because the new UI should be built on the intended long-term token owner rather than on the temporary `@config` bridge.

This is one coherent minor release, but not one indivisible implementation. Each workstream has a narrow public or operational contract, its own review gate, and the smallest deterministic tests that can establish it.

- a permanent fake Egregore runtime for deterministic development and tests;

The current boundaries also explain the release:

## Chosen approach and rejected alternatives

### Chosen: one canonical collection-resolution layer

Resolve Blog and Works ordering, Homepage selection, display data, and list-schema membership in pure typed utilities. Astro pages consume those resolved collections for both server-rendered HTML and JSON-LD. React receives serialized display records; it does not independently fetch, filter, or reorder repository content.

This makes one order authoritative for every consumer and prevents the visible surface, structured data, and tests from acquiring separate comparators.

### Chosen: Homepage spectacle, hub-page utility

Use depth carousels only for the two finite Homepage previews. Blog and Works hubs remain scan-first archives with static complete links, a shared two-column collection layout on desktop, and a one-column layout on mobile.

The visual carousel is therefore an enhancement to editorial presentation, not the only way to discover content.

### Chosen: Jet Web-owned carousel behavior on Framer Motion

Recreate the reference's depth, perspective, tint, blur, and layered movement with the existing Framer Motion dependency and semantic CSS tokens. Do not copy the React Bits component and do not add GSAP solely for this feature. Jet Web owns the state machine, server fallback, focus model, touch behavior, and active image-led metadata treatment.

### Chosen: CSS-first theme ownership before surface implementation

Move the raw palette, semantic utility aliases, fonts, fluid type utilities, fluid spacing utilities, dark selector, and typography plugin registration into CSS. Delete the legacy `tailwind.config.mjs` bridge after rendered equivalence is established. Keep regular runtime-only custom properties in `:root` when they should not generate Tailwind utilities.

Tailwind's official CSS-first model distinguishes `@theme` variables, which create utilities, from ordinary `:root` variables, which do not. That distinction becomes the repository contract.

### Chosen: constrained Markdown-to-React rendering

Adopt exact `react-markdown@10.1.0` with the existing `remark-gfm@4.0.1`. Raw HTML remains disabled. A dedicated Egregore response component owns safe element mappings and validated citation substitution without changing retrieval or generation.

### Rejected: tag navigation plus search

Keeping the full tag wall beside search would preserve the same expanding public taxonomy and split one discovery job between two competing controls. Tags remain searchable metadata, but the Blog hub exposes one search interaction.

### Rejected: carousel-only hubs

A depth stack hides most archive entries, reduces scanability, complicates filtering, and weakens static access. It is suitable for five-entry Homepage previews, not complete collections.

### Rejected: reuse `featured` as hidden priority

`featured` currently conflates inclusion, grouping, and public labeling. Keeping it under a new visual surface would retain ambiguous content semantics. Replace it with one explicitly Homepage-only numeric priority and remove the public Featured state.

### Rejected: copy the reference implementation or add GSAP

The reference is image-oriented and does not supply Jet Web's server fallback, companion information panel, link semantics, focus behavior, or scroll-safe touch model. A direct port would add a second animation runtime without removing product work.

### Rejected: preserve the Tailwind `@config` bridge indefinitely

The bridge was an intentional migration step in 2.2, not the final token architecture. Building the new card and carousel system on it would deepen a compatibility dependency and leave theme ownership split across JavaScript and CSS.

### Rejected: update every major dependency because it is newer

Recency alone is not a product requirement. Major changes enter `2.3.0` only when current compatibility evidence, a concrete benefit, and isolated verification justify them. TypeScript 7 and LiteRT-LM changes remain outside this release.

## Goals

1. Replace the Blog tag wall with accessible, shareable, metadata-aware search.
2. Make the Works hub one strictly newest-first collection with stable type filters.
3. Replace public Featured semantics with optional, Homepage-only work priority.
4. Give Blog and Works one intentional card anatomy without partial metadata inventories or arbitrary vertical bands.
5. Add two five-entry, manually looping Homepage depth carousels with high visual fidelity, complete server fallbacks, and accessible interaction.
6. Keep visible collection order and finite `ItemList` structured data derived from the same canonical resolvers.
7. Render safe, legible Egregore Markdown while preserving validated citations and local-only architecture.
8. Make article in-page navigation usable on desktop and mobile and make prose links visibly legible.
9. Move the Tailwind design-token and plugin configuration to CSS-first ownership without visual or browser-support regression.
10. Refresh and disposition the dependency and security graph under Node 24 while preserving explicit runtime pins.
11. Aggressively compact browser coverage and conservatively revalidate the regular suite around durable contracts.
12. Qualify site-wide structured-data coverage from built artifacts and add a publication-aware generated `llms.txt`.
13. Prevent local, CI, Preview, and opted-out developer-device traffic from entering the Production GA4 stream while keeping Search Console indexing controls correctly scoped.
14. Refine the Homepage carousel into a larger image-led overlay treatment without weakening fallback, input, motion, or schema contracts.
15. Publish the approved Human Agency essay and requested Spider-Man edits through the normal content and image workflow.

## Durable architecture

- Node 24.x and Astro 7 continue to statically render the site for Vercel.
- Tailwind CSS 4 continues through `@tailwindcss/vite`.
- `src/styles/global.css` remains the global stylesheet and imports one focused CSS theme owner, `src/styles/theme.css`.
- `theme.css` owns Tailwind-generating design tokens through top-level `@theme` or `@theme inline` blocks: palette utilities, semantic color utilities, fonts, Utopia-backed text sizes, and Utopia-backed spacing utilities.
- `global.css` owns ordinary selector-scoped runtime values, component recipes, base styles, dark overrides, and navigation geometry.
- Shader-only hexadecimal aliases remain ordinary custom properties because they support runtime WebGL values rather than Tailwind utility generation.
- `@plugin '@tailwindcss/typography'` replaces JavaScript plugin registration.
- `@custom-variant dark (&:where(.dark, .dark *))` remains the dark-mode selector contract.
- `@config` is removed and `tailwind.config.mjs` is deleted after equivalence qualification.
- Astro component style blocks that use Tailwind processing continue to reference the theme owner through the existing global `@reference` path or use ordinary custom properties directly.
- The supported browser floor remains Chrome 111+, Safari 16.4+, and Firefox 128+.
- Preflight, semantic color roles, Utopia fluid scaling, `.text-link`, `.action`, the Liquid Glass dock, Grainient, and forced-colors/reduced-motion behavior remain intact.

### Dependency ownership

- `package.json` remains the direct dependency authority and `package-lock.json` remains the exact resolved graph.
- Audit and update commands run under Node 24.x from a clean install.
- Compatible patch and minor upgrades may move together only when their platform set is coupled; unrelated major upgrades remain isolated.
- The Astro platform set moves together when required by peer and nested Vite compatibility.
- New Egregore Markdown support adds exact `react-markdown@10.1.0`; `remark-gfm@4.0.1` remains the GFM plugin.
- The public Egregore license bundle and `THIRD_PARTY_NOTICES.md` cover those direct renderer packages and every additional browser-distributed notice required by their resolved graph; package-manager metadata alone is not the shipped notice surface.
- Remote intrinsic-image verification adds exact dev-only `sharp@0.35.3` as the owned decoder for every supported source format. Its install surface, Apache-2.0 license, and transitive graph receive the same audit review as the rest of the matrix.
- TypeScript remains on the current 6.x line compatible with `@astrojs/check`; TypeScript 7 remains excluded.
- LiteRT-LM remains exactly 0.14.0 until its model/runtime qualification is explicitly repeated in another approved scope.
- Every reported advisory receives a disposition: removed, upgraded, unreachable/build-only with current patched resolution blocked upstream, or explicitly accepted with owner and rationale. A raw audit count without resolved-path analysis is not a disposition.
- The final clean lockfile must not retain a fixable advisory merely to avoid a compatible transitive refresh.

### Content and collection data

Published Blog and Work records require an authored, complete `summary` of at most 160 characters. Drafts may remain incomplete. Publication-aware validation, not an incidental card fallback, enforces the requirement.

Every published Blog and Work record also requires featured artwork at exactly 1920×1080 pixels, a 16:9 aspect ratio, an immutable public URL, and descriptive alternative text. Work `darkUrl` artwork must use the same intrinsic dimensions as its light counterpart. Repository validation checks the declared and remote intrinsic dimensions; card rendering may responsively downsample but never invent a different source ratio.

Work frontmatter removes `featured` and adds:

```ts
homepagePriority?: number;
```

`homepagePriority` is a positive integer used only by Homepage resolution. Lower numbers have higher priority. Published Works resolve in this order on the Homepage:

1. entries with a priority, ascending by priority;
2. equal-priority entries, newest date first;
3. entries without a priority, newest date first;
4. equal-date entries, stable ascending content ID.

The Homepage takes the first five resolved Works. The Works hub ignores `homepagePriority` and always sorts by date descending, then stable ascending ID. The Homepage Blog list is the five newest published posts by publication date descending, then stable ascending ID.

Tags remain in frontmatter, OpenGraph article metadata where applicable, JSON-LD keywords, RSS categories, Blog search fields, and Egregore retrieval. Tags are not rendered as public card rows, hub controls, or detail-page chip inventories.

One pure collection-resolution module owns published membership, these comparators, and serializable display records. It accepts raw collection entries, applies the canonical `isPublished()` policy before touching publication-required display fields, and returns published-only arrays. Pages and schema builders consume its output rather than reimplementing publication filters or order. Detail-route generation continues to call the same canonical publication policy directly.

### Shared collection-card system

Blog and Work cards use one shell with this element order:

1. fixed 16:9 media;
2. optional short content-type eyebrow;
3. title;
4. complete authored summary;
5. concise type-specific facts.

The media viewport always uses `aspect-ratio: 16 / 9` and fills the card's available inline width. At the existing 72rem `Container` maximum, the two-column hub layout produces approximately 33.25rem (532px) per card after fluid gutters and the inter-column gap, with an approximately 299px-high media viewport. Those figures describe the maximum-container result, not fixed card widths. Below 48rem, the grid becomes one column and each card uses the available width inside `px-gutter` while preserving 16:9.

The shell owns border, radius, overflow, media behavior, padding, focus, hover, row stretching, and vertical rhythm. Blog and Work adapters own semantic facts:

- Blog: publication date and reading time.
- Research: Research eyebrow, date, and venue when useful.
- Project: Project eyebrow and date.
- Other: Work eyebrow and date.

Cards do not render tags, `+N` counters, partial technology lists, Featured state, or external-action footers. Work external destinations remain on detail pages. Essential title, summary, and facts are not line-clamped. The authored summary must already be a complete editorial unit.

`collection` and `compact` remain only as deliberate density variants. Both use the same anatomy and semantics. `collection` serves hub cards; `compact` serves static Homepage fallback and other explicitly dense contexts. Neither variant uses fixed minimum-height bands for individual regions.

Blog and Works hubs share a two-column grid at widths of 48rem and above and one column below 48rem. Equal grid-row height may stretch the outer card; internal rhythm remains content-driven.

### Blog search

The Blog hub server-renders every published post in canonical newest-first order and a hidden-until-enhanced search control. Without JavaScript, the complete collection remains visible and navigable.

With JavaScript, one search field filters and ranks normalized `title`, `shortTitle`, `description`, `summary`, and `tags`. Normalization trims whitespace, applies Unicode compatibility normalization, folds case, removes combining marks for matching, and tokenizes on non-letter/non-number boundaries.

Every distinct non-empty query token must match at least one indexed field. For matching records, ranking compares this tuple lexicographically in descending order:

1. exact-title equality: `1` when the complete normalized query equals normalized `title` or `shortTitle`, otherwise `0`;
2. title-phrase presence: `1` when the complete normalized query is a contiguous substring of normalized `title` or `shortTitle`, otherwise `0`;
3. number of distinct query tokens present in `title` or `shortTitle`;
4. number of normalized tags exactly equal to the complete query or to one distinct query token;
5. number of distinct query tokens present anywhere in tags;
6. number of distinct query tokens present in `summary`;
7. number of distinct query tokens present in `description`.

A token may contribute to more than one field count; higher-precedence tuple positions decide first. Publication date descending and NFC-normalized content ID ascending by JavaScript code-unit comparison are the final deterministic tie-breakers. Cross-field matches are valid so long as every query token matches somewhere. The contract is this tuple and deterministic result order, not any private weighting helper.

The canonical query parameter is `q`. Initialization restores `q`; editing uses `history.replaceState`; clearing removes it. Invalid or whitespace-only input normalizes to the empty newest-first state. The canonical page URL remains `/blog/` regardless of client query state.

The search control has a programmatic label, visible clear action when non-empty, polite result-count announcement, useful empty state, and normal keyboard/focus behavior. Search does not highlight or generate excerpts in this release.

### Works discovery

The Works hub server-renders one complete newest-first collection. Progressive enhancement exposes All, Research, Projects, and Other only when that last category exists. The `type` URL parameter, pressed-state semantics, result announcement, invalid-value normalization, and no-JavaScript full-collection fallback remain.

Filtering changes visibility only. It does not regroup, reorder, or rewrite structured data. The Featured section, All Works secondary heading, Featured badge, and `featured` content field are removed.

### Homepage depth carousels

Homepage Latest Articles and Latest Works each receive one independent five-entry depth carousel. The state machine stores only the active canonical index and interaction state. Circular arithmetic owns every input:

```ts
next = (current + delta + itemCount) % itemCount;
```

Advancing from the final item reaches the first; moving backward from the first reaches the final. There is no cloned first-item sentinel in canonical data, either active representation, or schema. The Astro fallback and enhanced client tree may coexist physically during progressive enhancement, but exactly one is exposed or interactive at a time; that mutually exclusive handoff is not loop simulation.

Supported inputs are previous/next buttons, Left/Right Arrow keys while the carousel owns focus, horizontal swipe, and deliberate horizontal drag. Pointer handling must preserve normal vertical page scrolling and must not navigate during a drag. Selecting a receded card promotes it to active. Tapping or activating the active image-led card follows its canonical destination; Previous/Next always changes selection and never changes meaning.

The active carousel media surface uses `width: min(100%, 36rem)` with a 16:9 aspect ratio: at maximum size it is exactly 576×324px. Below that width it scales fluidly to the available section width without horizontal overflow. The bounded desktop stage may grow to approximately 60rem so receding layers and flanking controls remain contained.

The stage displays the active image with three perceptible receding layers at widths of 48rem and above and two at widths below 48rem. Receding layers may extend visually beyond the active surface only within the bounded stage; the stage must contain them without creating document-level horizontal scrolling. It uses CSS perspective, increased lateral spread, Y-axis tilt, graduated scale/depth, semantic tint/brightness, restrained blur, layered shadows, and smooth snapping. Hover or keyboard focus may slightly increase spread and visual depth, but idle cards do not move.

The active card owns a theme-aware lower-third vignette. At rest, Blog shows its title and Work shows its type plus title. Hover and `focus-within` ease the title upward and reveal the complete summary and concise facts through opacity and transform only; disclosure does not change the stage's geometry. Reduced motion removes the easing while preserving the same information state. The former companion panel is removed.

Touch layouts do not depend on hover. Blog always shows title, publication date, and reading time; Work always shows type, title, and date. The expanded summary remains a desktop hover/focus affordance. Swipe and Previous/Next change selection, a receded-card tap promotes that card, and an active-card tap follows its destination. Controls flank the image on desktop and remain below it where narrow geometry cannot preserve the 44px target floor without covering content.

Framer Motion drives a visible-triggered React enhancement beside one Astro-owned fallback tree. The server output contains every member once as compact static cards with canonical links and canonical order; the island server-renders no second collection. Because Astro observes an island's rendered children for `client:visible`, the island emits one inert, non-collection sentinel with a real intersection box on the server and matching first client render. That sentinel contains no collection content or destination. When the boundary approaches the viewport, hydration mounts the enhanced stage and removes the sentinel only after the stage commits. The enhancement then marks the fallback `hidden`, `inert`, and `aria-hidden="true"` before exposing its own accessible tree. If mounting or a later carousel render fails, the enhancement boundary restores the fallback before surfacing the failure. Teardown removes enhancement-owned state. This avoids hydration mismatch, focusable duplicate links, and deletion of the server semantic collection. The serialized island input contains only carousel display fields, not Blog-search metadata.

Controls meet the 44-by-44-pixel target floor. The active position is announced as “Item N of M,” where `M` is the resolved collection length; indicators expose their destination position; images retain descriptive alternatives; focus remains visible; and reduced motion uses immediate or minimal state changes without removing circular navigation.

There is no autoplay, timer, hover advance, vertical-wheel interception, infinite DOM duplication, or background motion while the carousel is idle.

### Collection structured data

Add one `itemlist` structured-data type to the shared builder. It accepts one finite resolved collection and produces:

- a stable page-scoped `@id`;
- a descriptive name;
- one-based `ListItem.position` values;
- unique canonical item URLs and entity `@id` references;
- no interaction state or duplicate loop item.

Homepage emits `#latest-articles` and `#latest-works` list identities from the same five-entry arrays passed to the carousel islands. The Blog hub emits `#blog-posts`; the Works hub emits `#works-collection`. Both hub lists are complete, canonical, unfiltered, and derived from the same arrays passed to the rendered grids.

Blog entries reference their detail-page `#blogposting` identities. Research entries reference `#scholarlyarticle`; Projects and Other reference `#creativework`. Detail pages remain the complete entity owners. The collection lists do not claim Google rich-result eligibility and do not copy every detail-page property.

### Site-wide structured data and public discovery

One build-artifact verifier discovers emitted HTML routes rather than maintaining an exact route inventory. It parses every JSON-LD block, verifies schema context/type and canonical agreement, rejects duplicate page-local identities, validates `WebPage`/main-entity links, and checks that ItemList membership is finite, unique, contiguous, canonical, and represented by visible page destinations. Collection-detail expectations derive from published content rather than named fixtures. Google Rich Results validation remains an RC observation against representative Production URLs rather than a network-dependent routine test.

The canonical profile adds `organizationUrl: https://digitalsquad.com/`. The visible words “Digital Squad” on About link to that URL. Homepage and About `Person` entities describe the affiliation through `worksFor` with one linked `Organization`; the employer is not added to the person's `sameAs` identities.

`/llms.txt` is statically generated at build time from the same publication-aware Blog and Works resolvers. A composition boundary accepts raw content entries, invokes those canonical resolvers, and passes only resolved published records to a pure formatter. It contains one site title/summary, selected core public routes, and exactly one list item for each currently published Blog and Work destination with its authored summary. New valid published records enter automatically; drafts, dormant Tools, license plumbing, assistant-corpus artifacts, tags, and private metadata do not. Titles escape Markdown link-label metacharacters, summaries collapse line breaks and repeated whitespace to one line, and canonical URLs remain unchanged. The response is concise Markdown-flavored plain text with `text/plain; charset=utf-8`. It complements rather than replaces robots, sitemap, structured data, or Egregore's separately governed corpus.

### Analytics isolation

The GA4 tag is deny-by-default outside a Vercel Production build. Local development, local production-mode builds/previews, CI, and Vercel Preview artifacts do not emit the Production measurement tag or page-view events.

Production supports a persistent site-wide developer-device opt-out established before Partytown or GA4 event configuration. `?analytics=off` writes `jet_analytics_opt_out=1; Max-Age=31536000; Path=/; Secure; SameSite=Lax`; `?analytics=on` clears the same site-wide cookie with `Max-Age=0; Path=/; Secure; SameSite=Lax`. Both controls remove only the `analytics` parameter from the visible URL while preserving unrelated query parameters and fragments. One idempotent controller processes the initial document and every ClientRouter navigation before page-view configuration, sets `window['ga-disable-' + measurementId]` from the resulting state, and owns at most one page-load sender. An opted-out browser sends no GA4 configuration or collection event; clearing the opt-out restores ordinary Production measurement without duplicate listeners or events. This provides a stable device-level boundary when IP-based internal-traffic rules are unsuitable for mobile or changing networks. GA4 hostname/internal/developer filters remain optional account-side defense in depth and must be tested before activation.

A dedicated local Production-build fixture qualifies both analytics branches on an isolated port. It intercepts GA library and collection endpoints before navigation, so qualification can observe intended configuration and page-view behavior without sending real traffic. The enabled branch observes the library request plus one configuration/page-view sequence. The opted-out branch may fetch the inert library but emits zero configuration, page-view, or collection requests. Routine browser tests separately prove that non-Production artifacts contain no Production analytics surface or Google requests.

Search Console is not visit analytics. Its isolation contract remains canonical Production URLs plus Preview/outdated-deployment `noindex` headers and sitemap exclusion where appropriate; no application code claims to filter ordinary user visits from Search Console.

### Egregore Markdown rendering

Create a focused assistant-response renderer rather than extending `CitedResponse` in the already large experience component. It accepts one `ConversationTurn` and allows only these parsed Markdown nodes:

- paragraphs and soft line breaks;
- emphasis and strong text;
- ordered and unordered lists;
- blockquotes;
- inline and fenced code;
- headings mapped to an in-chat hierarchy that does not compete with the page `h1`;
- safe links;
- validated source citations.

Raw HTML stays disabled. Model-authored images never emit `<img>` or initiate a remote request; their alternative text is retained as inert text. Tables, task-list controls, strikethrough, embedded HTML, and every other unsupported GFM/HTML node are unwrapped to safe text or omitted without discarding ordinary textual content. Link destinations allow `https:`, `http:`, `mailto:`, and same-document fragments only. External HTTP(S) destinations open in a new tab with `rel="noopener noreferrer"`; fragments and mail links do not acquire that behavior. Unsupported or malformed destinations render as text rather than active links.

After Markdown parsing, a remark AST transform examines ordinary text nodes only. It skips code, inline code, links, images, escaped markers, and every unsupported node. Only citation markers whose identifiers exist in the turn citation map become renderer-owned citation nodes; unvalidated `[S#]` text remains ordinary text. The citation component retains its canonical source URL, accessible label, mustard treatment, and Response Details relationship. User turns remain plain text.

Streaming may end at an incomplete Markdown delimiter. The renderer must preserve all received text, avoid throwing, and settle naturally when more content arrives. It does not reparse retrieval sources, mutate the turn, or change prompt assembly.

### Long-form article navigation and links

Desktop Blog layout owns the sticky containing block. The article and contents share one grid whose height is established by the article. The contents `aside` itself is `position: sticky`, `align-self: start`, and top-offset; it does not wrap a second sticky child. No ancestor between it and the viewport may establish clipping or an incompatible scroll container.

One lifecycle-safe table-of-contents controller owns active-section observation. It initializes on direct load and `astro:page-load`, disconnects any previous observer before reinitializing, observes only headings represented in that article's contents, and updates both desktop and mobile views from one active-section state.

Below the desktop breakpoint, a compact sticky `On this page` disclosure renders the current section label and expands to the complete heading list. It is a native button/disclosure interaction with accurate `aria-expanded` and `aria-controls`, visible focus, dock-aware bottom clearance, and no large permanent overlay. Selecting a heading closes the disclosure and preserves normal fragment navigation.

Blog and Works prose links use a content-scoped accent link recipe based on `accent-text` with deliberate hover, focus, dark-theme, forced-colors, and reduced-motion behavior. Navigation, cards, buttons, citation markers, and global `.text-link` consumers do not inherit this change.

Back to blog and Back to works remain one semantic anchor each. The arrow and label become separate children, and underline decoration applies only to the label child on hover or focus.

## Error handling and progressive enhancement

- Missing required published summaries fail content verification and the build with the content ID and field name.
- Duplicate or invalid Homepage priorities remain deterministic through date and ID tie-breakers; invalid non-positive or non-integer values fail schema validation.
- Collection limits are positive integers; an invalid internal limit fails immediately. Carousel index wrapping is defined only for non-empty collections and throws for an empty collection; empty sections never invoke it and render the existing useful empty state.
- Fewer than five published entries render all available entries. Zero entries render the existing useful empty state. Carousel controls are omitted when fewer than two entries exist.
- Blog search with a malformed `q` value normalizes safely to a string, never injects markup, and may return an empty state.
- Works with an unknown `type` query returns to All and removes the invalid parameter.
- A response-level render boundary falls back to whitespace-preserving plain text if the Markdown component unexpectedly throws. It must not discard the underlying response text or terminate the surrounding conversation. The renderer's normal contract remains non-throwing for arbitrary model text.
- Carousel enhancement failure leaves the server-rendered static collection usable.
- Structured-data construction rejects duplicate canonical membership in development and tests; production data resolution prevents it upstream.
- Dependency updates that fail a platform, build, content, browser, or artifact contract are reverted or isolated; failures are not hidden behind overrides without resolved-path justification.

## Test-contract revalidation

### Browser suite

Treat every existing browser test as suspect by default. Retain browser execution only for an important user-visible durable contract that cannot be established adequately in the regular suite. Suitable owners include browser navigation lifecycle, focus and keyboard flows, responsive disclosure behavior, computed sticky positioning, touch/drag behavior, reduced-motion rendering, no-JavaScript fallbacks, and deployed routing or headers.

Delete, merge, or demote browser tests that freeze incidental copy, counts, current entries, CSS classes, internal wrappers, fixture call graphs, or historical implementation seams. Do not preserve test count or nominal coverage.

### Regular suite

Preserve broad deterministic coverage of content policy, schemas, collection resolution, search normalization and ranking, card semantics, structured-data generation, Markdown safety and citation mapping, operational scripts, build artifacts, and deployment contracts. Remove only clearly redundant, dead, skipped-without-purpose, implementation-coupled, or low-value tests.

Source-level tests remain appropriate when the source or generated artifact is the declared contract, such as package scripts, build purity, license bytes, or production artifact exclusions. They do not become appropriate merely because an implementation is easier to inspect than its behavior.

### Perturbation qualification

After compaction, qualify the complete regular and browser suites repeatedly against temporary representative content changes:

- add one valid published Blog record;
- change non-contractual editorial copy and punctuation;
- vary tag number, length, and labels;
- change dates and Homepage priorities;
- add a valid Work without external links;
- use long but schema-valid titles and complete summaries.

Restore all perturbations after qualification. Fix root causes. Do not add retries, larger timeouts, broad skips, or fixture-specific assertions to recover green. Do not retain a meta-test whose only purpose is proving that this audit occurred.

## Accessibility, visual, and performance qualification

Qualification covers light and dark themes, keyboard-only use, visible focus, reduced motion, forced colors where applicable, and representative desktop and mobile viewports. Routine CI remains Chromium-based. Release qualification additionally runs current Chromium, Firefox, and WebKit Playwright engines from a fresh build-owned server. Because those engines do not emulate historical versions, the declared Chrome 111+, Safari 16.4+, and Firefox 128+ floor is also encoded as the Vite build target and reviewed for unsupported runtime APIs/CSS rather than falsely claimed from current-engine execution alone.

Visual review includes:

- long and short Blog and Work card content;
- two-column and one-column hubs;
- carousel depth, tint, blur, shadows, companion-panel stability, first/last looping, and fallback state;
- Blog search result, clear, empty, URL-restoration, and no-JavaScript states;
- Works filters and no-JavaScript state;
- Egregore paragraphs, lists, links, code, headings, citations, and incomplete streamed Markdown;
- desktop sticky contents, mobile disclosure, fragment navigation, prose links, and Back-link underline boundary.

Carousel performance is measured with both Homepage carousels, Grainient, and the Liquid Glass dock present. Begin with three receding desktop layers and two at representative mobile viewports. Prove that the below-fold carousel chunk and enhancement-only work wait for the visible-trigger boundary. Fallback image loading remains browser-managed through native `loading="lazy"`; it is not treated as an exact request-timing contract. Tune nonessential offscreen work, blur radius, shadow complexity, serialized island data, and compositor promotion only from evidence. Do not silently flatten the defining depth effect to satisfy a synthetic metric.

There is no physical-device gate for `2.3.0`. Supported-browser qualification at representative desktop and mobile viewports is sufficient. Any later real-device observation is supplementary evidence, cannot become a durable test, and cannot retrospectively block this release.

## Acceptance criteria

`2.3.0` is acceptable when all of the following are true:

- Blog has one accessible `q` search and no public tag wall or tag chips.
- Empty Blog search restores complete newest-first order; active search follows the declared field precedence and deterministic tie-breakers.
- Works displays one newest-first sequence with stable type filters and no public Featured state.
- Homepage Works respects optional ascending `homepagePriority`, then newest-first date and stable ID.
- every published Blog and Work has a complete authored summary;
- every published Blog and Work card source is verified 1920×1080 artwork with descriptive alternative text;
- collection cards share one anatomy and contain no `+N` metadata, partial technology list, Featured badge, or external footer;
- collection media remains fluid 16:9, producing approximately 532×299px card media at the maximum two-column hub width and one available-width column below 48rem;
- each Homepage section contains up to five unique entries, uses a maximum 576×324px active image-led surface, loops manually in both directions, has no autoplay, does not hydrate before its visible boundary, and remains useful without JavaScript;
- Homepage and hubs emit finite unique ItemLists whose positions and identities match the canonical server-resolved collection order;
- every emitted HTML route has parseable, canonically linked JSON-LD at the appropriate page boundary, and `/llms.txt` projects all and only published Blog/Work destinations from canonical resolvers;
- About visibly links Digital Squad and the canonical Person entity connects that affiliation through `worksFor` without corrupting `sameAs`;
- local, CI, Preview, and opted-out developer-device execution sends no Production GA4 events, while Production indexing behavior remains separately governed through canonical, sitemap, and robots contracts;
- desktop carousel hover/focus reveals complete metadata without layout movement; touch layouts expose stable title and primary facts without hover dependence; controls retain one predictable meaning;
- Human Agency is published with its approved content, verified immutable 1920×1080 hero, natural internal/external links, and assistant eligibility; Spider-Man contains only the requested contraction, approved heading updates (three replacements and one new heading), and updated date change;
- Egregore renders the supported Markdown semantics, rejects raw HTML and unsafe links, preserves arbitrary incomplete text, and links only validated citations;
- desktop article contents are observably sticky, mobile articles expose the compact sticky disclosure, prose links are legible in both themes, and Back arrows are not underlined;
- CSS owns all Tailwind-generating custom theme values and typography registration; `@config` and `tailwind.config.mjs` are gone without visual or browser-support regression;
- the final dependency matrix is recorded, the lockfile is cleanly reproducible under Node 24, every advisory is disposed, TypeScript remains 6.x, and LiteRT-LM remains exactly 0.14.0;
- the compacted suites pass repeatedly and survive the declared temporary content perturbations;
- routine Chromium plus release Chromium/Firefox/WebKit responsive and performance qualification passes from fresh build-owned servers, and the compiled target/API review supports the declared minimum versions without a physical-device gate;
- the integrated review finds no critical or important unresolved issue, Production is verified directly, and repository documentation describes the resulting system rather than the cleanup history.
