# Jet Web 2.2.0 Design

**Status:** Approved for implementation

**Date:** 2026-07-18

**Release target:** `2.2.0`

**Implementation plan:** [Jet Web 2.2.0](../plans/2026-07-18-jet-web-2.2.0.md)

**Evidence source:** [Jet's Ghost 2.1.0 qualification and post-release record](../../verification/jets-ghost-2.1.0.md)

## Executive decision

Ship the approved post-`2.1.0` work as one coherent `2.2.0` release. The release adds first-class, About-backed profile grounding to Jet's Ghost and carries the already committed Digital Squad Timesheet work, so it is a backward-compatible minor release rather than a maintenance patch.

`2.2.0` is not a new site architecture or assistant redesign. It hardens the modernized Astro application, removes release residue, gives the local model durable browser storage, corrects physical-mobile failures, and makes the repository and test suite read as intentional current software.

The implementation is organized as independently reviewable workstreams, but they share one release contract and one final gate. This avoids two failure modes:

- a loose backlog of unrelated patches with no coherent completion condition;
- a monolithic qualification ceremony in which every change triggers every historical check.

## Current baseline

The implementation starts from the canonical `/Users/jet/jet-web` repository at local commit `27afb67dc169d5fd725d6e78457e5ee84e66145e`. That commit is three commits ahead of `origin/main`: the published, assistant-enabled Digital Squad Timesheet case study; the unified Blog/Works/Home content-card architecture; and the follow-up hardening of shared card and untracked-content contracts.

The only known local changes at design time are the post-release evidence record and user-owned material under `Untracked/`. `Untracked/` is never an implementation input, formatting target, lint target, content source, or release-staging source.

## Chosen approach and rejected alternatives

### Chosen: one release with explicit system boundaries

Use one `2.2.0` design and plan with separate boundaries for content grounding, model storage, mobile layout, mobile runtime stability, dock rendering performance, repository hygiene, and release operations. Each boundary receives the smallest test and qualification that can prove its public contract.

### Rejected: split maintenance into `2.1.1` and defer capability work

The physical-mobile layout defects could be patched independently, but the approved scope now includes a new assistant capability, model caching, tooling, and repository cleanup. Splitting the work would duplicate release coordination while leaving the current documentation and test ownership ambiguous.

An urgent independently verified production defect may still justify a patch before `2.2.0`, but the current plan does not assume one.

### Rejected: preserve the completed `2.0.0` and `2.1.0` plans as active authorities

Those documents contain durable historical reasoning but also contain completed containment steps, superseded route states, paired real-model ceremony, and the instruction that caused the missing GitHub Release. They will be archived as release history after their still-current constraints are carried into this design and `AGENTS.md`.

## Goals

1. Make `/about/` the single canonical source for Jet's public profile and make that source available to Jet's Ghost with normal provenance and citations.
2. Persist the exact pinned model in Cache API after explicit activation, without time-based expiry or a second storage subsystem.
3. Correct the confirmed Xiaomi 14T layout defects and obtain enough device evidence to make an honest runtime-support decision.
4. Improve visible Liquid Glass dock performance toward sustained `60fps+` on the Xiaomi 14T without an intentional visual or behavioral change.
5. Make every retained test, fixture, script, document, and support path express a current public or operational contract.
6. Adopt Prettier and ESLint as separate, deterministic repository gates after obsolete test and documentation surfaces are removed.
7. Reconcile legal links, navigation ownership, contributor guidance, release records, SEO, Search Console follow-up, and versioning.
8. Release `2.2.0` through proportional qualification rather than repeating the complete `2.1.0` ceremony.

## Non-goals

- No retrieval redesign, retrieval benchmark programme, embedding model, reranker, PGlite, pgvector, EntityDB, or additional ranking strategy.
- No change from the deterministic MiniSearch rank-and-token-budget packer.
- No model change, E4B switching, hosted inference fallback, tool use, multimodality, or persistent conversation history.
- No CMS, Cloudflare, server adapter, Tailwind 4, Astro major-version, or broad dependency migration.
- No visual redesign of Jet's Ghost, the Liquid Glass dock, or the site identity.
- No device-specific visual downgrade, opaque dock fallback, reduced animation, or lower-quality model behavior introduced merely to pass a metric.
- No new heavyweight mobile performance job or approximately `2 GB` model download in routine or nightly CI.
- No test, script, snapshot, or CI gate whose purpose is to prove that the cleanup itself happened.
- No Git history rewrite, release-tag movement, or publication of user-owned `Untracked/` material.

## Durable architecture

### Site

- Astro 5 statically renders the site for Vercel.
- MDX and typed content collections own published material.
- React remains limited to stateful browser islands.
- `npm run build` remains pure and performs no external write.
- Public content requires `status === 'published'`.
- Jet's Ghost content additionally requires `assistant === true`.
- Canonical URLs, navigation, OpenGraph URLs, JSON-LD, and sitemap entries use the trailing-slash route contract.
- The shared document-title separator remains ` | ` through the canonical SEO formatter. Center dots used inside compact product copy are not document-title separators.
- The semantic OKLCH palette, Utopia type and spacing, `.text-link`, `.action`, and card recipes remain the design-system contract.

### Jet's Ghost

- `/chatbot/` remains the canonical indexed route; `/tools/chatbot/` remains a permanent legacy redirect and `/tools/` remains dormant and noindexed.
- One pinned Gemma 4 E2B LiteRT-LM model runs locally after explicit visitor consent.
- Compatibility checks do not import the runtime, fetch the corpus or model, create an engine, or allocate the GPU.
- The immutable eligible corpus, stable source identifiers, heading-aware segmentation, provenance, citations, and corpus versioning remain intact.
- One deterministic MiniSearch rank-and-pack pipeline owns context selection through the accepted one-to-two-million eligible-token design boundary.
- The assistant refers to Jet in the third person, does not speak on his behalf, answers only from supplied published sources, and abstains when evidence is absent.
- Only validated citations actually used in a response are exposed to visitors.
- Prompts and conversation state remain session-only and local to the browser.
- The fake runtime is permanent deterministic development and test architecture, not modernization residue. Audit its individual scenarios and instrumentation and remove only genuinely orphaned cases; preserve its lifecycle, failure, privacy, responsive, and interaction coverage. It must remain unavailable and absent from Production artifacts.

## Workstream 1: canonical profile grounding

Create a `profile` content collection with one tracked record, `jet-sanchez`. The record uses the same deny-by-default publication fields as Blog and Works and is both `published` and assistant-enabled. It owns:

- the substantive About biography;
- public role and organization context;
- research areas and technical focus;
- the About description and other changing biographical facts needed by the page and assistant.

`/about/` renders this record rather than maintaining a second copy in page markup. Home and About also read its role for Person structured data; remove the duplicate biographical `SITE.jobTitle` field so the profile remains the canonical role source. The same record enters the versioned assistant corpus with stable document ID `profile:jet-sanchez` and canonical URL `https://jetsanchez.com/about/`; it must never produce a `/profile/jet-sanchez/` public route.

The profile extends the existing content-policy and corpus unions without changing their core eligibility predicate. It receives normal source-path, Git-tracking, source-hash, section, chunk, corpus-version, rank-and-pack, and citation treatment. Current corpus counts are evidence snapshots, not acceptance thresholds.

The system prompt retains relationship and behavior instructions only. It may say that Jet's Ghost helps visitors understand Jet Sanchez's published work and profile, that Jet is the person whose work it interprets, and that it must refer to him in the third person. It must not duplicate occupation, employer, biography, or research facts that belong in the profile source.

Acceptance requires useful, third-person, About-cited answers to **Who is Jet?** and **What does Jet do?**, plus grounded answers about his work and research. Unsupported personal claims must still use the established abstention contract.

## Workstream 2: persistent pinned-model storage

Introduce one browser-owned model-source boundary between `LiteRtGemmaRuntime` and the pinned model URL. The boundary resolves either:

- a `ReadableStream<Uint8Array>` from the exact committed Cache API response; or
- the existing pinned URL for an explicit uncached attempt.

Use one versioned Cache Storage namespace whose identity includes the cache schema and exact model SHA-256. Use the pinned repository revision and filename in the request key. A model-version change produces a different identity and removes obsolete Jet's Ghost model cache namespaces; an application-version change does not.

On a cache hit, return the stored response body without a model-network request. On a miss:

1. fetch the exact pinned URL only after **Load Jet's Ghost**;
2. require the reviewed trusted-origin, redirect, status, and expected-length contract;
3. complete `cache.put()` without cloning or teeing the approximately `2 GB` body;
4. read the committed response back from Cache API;
5. pass that response body to LiteRT-LM.

If Cache API is unavailable during preflight, the visitor may explicitly continue with the existing uncached URL path. If a cache write fails after download begins, do not silently start a second approximately `2 GB` transfer; surface a recoverable state with an explicit uncached retry.

The cache is best-effort browser storage. It has no TTL, timestamps, expiry timer, service worker, IndexedDB, OPFS, background cleanup, or application-version invalidation. **Unload** releases only conversation, engine, runtime, GPU, and memory state. A separate **Remove downloaded model** action deletes the model cache and appears only when a current cached model exists.

Deterministic small-response tests own interrupted writes, quota failure, eviction-like recovery, and retry authorization. The real-model qualification covers one cold commit, one warm reuse with no model-network request, reload survival, Unload preservation, privacy, and explicit removal at the end. The unchanged pinned bytes do not justify model-sized fault injection or repeated independent hash downloads on every deployment.

## Workstream 3: physical-mobile layout and runtime stability

### Layout

Mobile browser chrome exposes the current failure, but it is not the architectural owner of the fix. The fixed dock overlays layout without reserving space, fresh immersive entry cannot discover its control through document scrolling, and the Ghost shell can enforce a `40rem` minimum while its body is clipped. Keep `svh` unless device evidence establishes a separate viewport-unit defect; instead make short visual viewports, dock state, and immersive scrolling explicit contracts.

#### Dock discovery and visibility

Dock discovery and mobile dock visibility are independent session state:

- A fresh ordinary mobile document starts with the dock open and the disclosure undiscovered. The existing qualifying first-document-scroll interaction marks it discovered and closes it.
- A fresh mobile immersive layout starts with the dock open and the disclosure immediately available. It must not require prior navigation or document scrolling that the immersive shell cannot perform.
- An explicit visitor choice of open or closed persists across Astro client navigation, full reload, and back/forward history in the same tab. A non-dock link must not reopen a dock the visitor closed.
- Desktop and tablet layouts at `48rem` and above always expose the dock and do not render the mobile disclosure. Crossing that breakpoint suspends rather than deletes the remembered mobile preference; returning below `48rem` restores it.
- A new tab session without retained session state returns to the fresh open state.

Persisting a closed state also establishes discovery; a structurally valid closed-but-undiscovered value normalizes to discovered and remains closed so the visitor can reopen it. Missing state uses the route-appropriate fresh default. Malformed or unsupported retained data uses the fresh open state and is replaced on the next explicit toggle. Only unavailable or unreadable session storage falls back to operable page-lifetime state.

Pass the existing `immersive` layout boundary from `BaseLayout` through the dock wrapper. Do not special-case `/chatbot/` or infer layout mode from a pathname. Read retained session state before the dock's first interactive render so the interface does not visibly restore itself after mount. Use the same below-`48rem` boundary in JavaScript and CSS; do not let `768px` satisfy both mobile JavaScript and desktop Tailwind behavior.

The disclosure retains its current appearance and remains a semantic button with accurate `aria-expanded` and `aria-controls`. A closed dock is inert, hidden from the accessibility tree, and removed from sequential focus. Closing returns focus to the disclosure when focus was operating within that interaction. The state contract must not add a second dock, route-specific control, or persistent user-profile setting.

#### Ghost clearance and compact mobile content

Define one shared BaseLayout/navigation exclusion-zone contract from rendered dock placement rather than the state breakpoint alone:

- below `48rem`, the bottom overlay envelope reaches the highest occupied edge of the dock or raised disclosure control, plus the fixed bottom offset, normal separation, and safe-area inset;
- from `48rem` to below `64rem`, the always-open bottom dock has no disclosure but still owns a bottom exclusion zone;
- at `64rem` and above, the dock moves to the top and the immersive header owns the corresponding top separation instead of a bottom reserve.

The fixed navigation and every internally scrolling Jet's Ghost lifecycle surface consume that same contract; do not duplicate dock-height guesses inside Ghost. Keep each applicable exclusion zone stable across open/closed transitions so toggling does not reflow Ghost and reopening cannot cover content.

Do not retain the current below-`370px` exception as the only activation protection. Primary activation, consent, loading, recovery, pre-conversation, conversation, composer, and disclosure content must remain reachable and must not render beneath the fixed navigation while it is visible. Hiding the dock is a visitor preference and performance affordance, not the workaround required to use Ghost.

Below `48rem`, the Ghost shell must fit the actual short viewport instead of allowing `min-height` to force clipped content behind a non-scrolling body. Qualification includes a fresh `375 × 680` or shorter measured-phone viewport with the dock visible, not only the taller emulated Pixel and `430 × 932` cases.

At small-mobile widths below `48rem`, do not render starter-prompt buttons. Direct composition remains the primary task. Tablet and desktop layouts retain the prompts where they fit naturally; no carousel, chip scroller, or alternate mobile interaction replaces them.

Keep the exact reliability disclosure **Jet’s Ghost can make mistakes. Check cited sources.** immediately above the composer until the first submitted message. Use the existing Utopia `text-xs` tertiary/meta token on all viewports. The normal Xiaomi presentation should fit on one line, while zoom, enlarged text, localization, and constrained widths must wrap without clipping or horizontal overflow.

The composer, dock, header, loading hierarchy, and approved ghost animations retain their current visual treatment, motion language, and interaction semantics except for the explicit state and clearance corrections above.

### Runtime termination

The intermittent return from Chrome to the Android home screen is a separate process-level symptom. Screen mirroring can verify visible layout but cannot establish whether Android killed the renderer, Chrome crashed, the GPU process failed, or LiteRT exhausted a resource.

A USB-debugging evidence path is now established on the Xiaomi 14T. The `2026-07-18` baseline confirms Android 16, Chrome `150.0.7871.128`, a physical `1220 × 2712` display at density `520`, a current `60 Hz` presentation mode, and a `375` CSS-pixel page width at the observed browser scale. Available viewport height is dynamic under browser chrome and the software keyboard and must be captured in each tested state rather than frozen as a device constant.

The phone reported approximately `11.6 GB` total memory with approximately `3.8 GB` available during the probe. Android retained historical Chrome low-memory exits, but not an entry that can be correlated to the reported Jet's Ghost termination. This supports memory pressure as a credible hypothesis, not a diagnosis. Before another real-model attempt, begin a bounded ADB and Chrome evidence capture first and record only the minimum non-conversation facts needed to classify the termination. Do not repeatedly crash the device for benchmark completeness.

The release decision is evidence-based:

- if a contained runtime or lifecycle defect can be corrected without changing the pinned model or approved product behavior, fix it and require one bounded successful phone run;
- if the failure is a browser/platform limitation or cannot be corrected without reducing answer quality, changing the model, or manufacturing a misleading compatibility claim, stop and obtain Jet's explicit approval for the resulting supported-device boundary before release.

A fake-runtime responsive test can close the layout finding but cannot close the process-termination finding.

## Workstream 4: site-wide Liquid Glass dock performance

Treat mobile dock performance as site-wide pre-existing debt, not a Jet's Ghost or Grainient regression. Measure it on a cool Xiaomi 14T before loading the model.

Use one static route for the decisive comparison between visible and hidden dock states across idle, scroll, open, close, and post-transition intervals. Repeat only the decisive interval on Home to confirm that Grainient does not change the result. Record frame presentation, dropped or partially presented frames, paint/composite work, layer behavior, and memory. Temporary traces and instrumentation remain local unless a compact artifact has an explicit continuing owner.

Only implement changes supported by the trace, beginning with filtered-area lifecycle, duplicate filtered surfaces, layer ownership, displacement-map regeneration, resize observation, and repaint scope. Preserve distortion, translucency, shadows, geometry, icons, theme response, the Workstream 3 discovery/visibility contract, navigation, focus, reduced motion, and accessibility semantics.

The target is presentation at the device's current `60 Hz` ceiling within normal trace tolerance during the representative visible-dock interaction: at least `57` presented frames per second over the steady-state sample, no sustained visible jank, and no material hidden-state regression. If the device is deliberately tested in a higher-refresh mode, the floor remains `60fps`; the higher ceiling is not itself a requirement. This is a one-release decision signal, not a permanent automated benchmark. Preserve no intentional side-by-side visual difference in light or dark mode. If the SVG backdrop effect itself prevents that target, stop and present the measured visual-performance trade-off rather than silently weakening the dock.

## Workstream 5: intentional repository and test surface

The current tree should explain the current system without requiring reconstruction of the modernization thread.

Apply this contract throughout the tracked test surface:

> **Contract-Coupling Principle:** Every test must derive its assertions from an observable, durable contract at the narrowest appropriate boundary. For components, this includes public APIs, rendered semantics, interaction, accessibility, and explicitly standardized visual behavior. For modules, scripts, builds, CI, and security controls, it includes declared inputs, outputs, failure modes, generated artifacts, and invariants. Private helpers, source layout, call graphs, intermediate representations, CSS classes, and implementation choices are not valid test targets unless explicitly designated as compatibility or artifact contracts. A behavior-preserving refactor should not ordinarily break a test.

Add this principle to the testing guidance in `AGENTS.md` as a durable contributor rule. Its enforcement is the ownership and shape of the test suite itself, not a new meta-test.

Audit every tracked test, fixture, setup file, manual suite, and support module. Classify coherent coverage as behavioral, deliberate static/build/security contract, implementation-coupled, duplicate, or obsolete. Retain source inspection only when the checked text or artifact is itself the public or operational contract and no equally direct behavior proves it.

Remove annotation/session provenance from filenames, suite names, helper IDs, and descriptions. Rehome valid card, action, link, contrast, responsive, privacy, legal, routing, and artifact coverage under durable ownership. Remove duplicate, obsolete, and implementation-only checks instead of rewriting their expected strings. Add or replace a test only when the audit exposes a genuine otherwise-unprotected product, accessibility, privacy, security, publication, routing, or release boundary.

The audit remains a human review activity. Do not add a test, script, snapshot, count threshold, ratio gate, classification file, or CI job that proves the audit or forbids annotation-named files.

Other intentional-tree corrections in this release are:

- derive Footer navigation from shared site configuration and include Jet's Ghost;
- repair the four public local destinations in `THIRD_PARTY_NOTICES.md`;
- copy the fourteen obsolete Core 1.0 screenshot PNGs into the ignored local `Untracked/` evidence lane, remove them from the current tracked tree, and preserve their existing release history without a rewrite;
- add root `Untracked/` to the explicit ignore boundary without inspecting, moving, renaming, or publishing its contents;
- archive completed `2.0.0` and `2.1.0` specs, plans, and the prototype-era chat-experience note after their durable constraints are absorbed here and in `AGENTS.md`;
- freeze the `2.1.0` qualification document as completed evidence rather than leave it as an active backlog.

Audit every tracked non-archive documentation and evidence path, not only the named plans. Outside `docs/archive/`, retain only the active 2.2 design, implementation plan, and in-progress verification record. Move completed core modernization, containment, consolidation, license-review, and compact baseline evidence into their release-owned archive lanes after every still-current constraint has an active owner.

## Workstream 6: formatter and linter

Complete the test and documentation audit before establishing either tooling baseline.

### Prettier

Adopt pinned Prettier 3 with `prettier-plugin-astro`. The configuration implements the existing repository style: two-space indentation, semicolons, single quotes in TypeScript, double quotes in JSX attributes, LF endings, trailing commas where supported, and preserved Markdown prose wrapping.

Do not add Tailwind class sorting in this release. Sorting class strings does not solve semantic token or CSS cascade ownership and would enlarge the formatting baseline without a demonstrated correctness benefit.

Add `format` and read-only `format:check`. Exclude `Untracked/`, dependencies, build/generated output, Playwright and coverage artifacts, Vercel state, binary and staged image inputs, archived documents, and immutable historical evidence. Establish the maintained-tree format in one isolated commit with no product change.

### ESLint

Adopt a pinned ESLint 9 flat-config stack compatible with the current Astro, TypeScript, React Hooks, and JSX accessibility plugins. ESLint 10 is not required for this release while the accessibility plugin's declared peer range remains ESLint 9. Prettier owns formatting; ESLint owns correctness and maintainability.

Add `lint` and `lint:fix`, with `lint` failing on any warning. Apply the same maintained-tree boundary as Prettier. Narrow suppressions must explain a real external or architecture boundary; broad disables and severity reductions are not acceptable baseline techniques.

Add `format:check` and `lint` to the existing `npm run verify` command so the current pull-request, `main`, manual, and nightly workflow enforces them. Do not create another routine workflow, hook manager, staged-file daemon, Stylelint, Markdownlint, or Biome layer.

## Proportional qualification

Routine and nightly CI retain deterministic unit, content, documentation, formatting, lint, build, production-artifact, accessibility, and fake-runtime browser checks. They never download the real model.

The `2.2.0` candidate receives one combined production-equivalent real-model sequence because profile, corpus, prompt-facing behavior, and model delivery change:

1. cold activation commits the model cache;
2. ask **Who is Jet?**, **What does Jet do?**, one Timesheet/work-or-research question, and one unsupported private question, resetting between cases;
3. verify useful third-person grounding, About citation resolution, ordinary work citations, and unsupported abstention;
4. unload and perform one warm activation;
5. verify the warm path makes no model-network request and that cleanup/recovery remain credible.

Run this sequence once against one production-equivalent candidate. Do not duplicate it on both Preview and Production when the bytes and boundaries are unchanged. The physical-phone real-model portion occurs only after the termination evidence establishes that the Xiaomi remains a credible supported target.

Deployment verification remains focused on routes, redirects, metadata, schema, sitemap/robots, assets, corpus, privacy invariants, transport containment, and Production seam exclusion. A deployment alone does not trigger another model download or independent model hash.
