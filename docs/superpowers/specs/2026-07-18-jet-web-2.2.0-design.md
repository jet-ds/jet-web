# Jet Web 2.2.0 Design

**Status:** Approved for implementation

**Date:** 2026-07-18

**Release target:** `2.2.0`

**Implementation plan:** [Jet Web 2.2.0](../plans/2026-07-18-jet-web-2.2.0.md)

**Evidence source:** [Jet's Ghost 2.1.0 qualification and post-release record](../../verification/jets-ghost-2.1.0.md)

## Executive decision

Ship the approved post-`2.1.0` work as one coherent `2.2.0` release. The release renames the maintained local assistant from Jet's Ghost to **Egregore**, adds first-class About-backed profile grounding, and carries the already committed Digital Squad Timesheet work. Because `/chatbot/` and the runtime behavior remain compatible, this is a backward-compatible minor release rather than a maintenance patch or major-version change.

`2.2.0` is not a new site architecture or assistant redesign. It hardens the modernized Astro application, removes release residue, gives the local model durable browser storage, corrects physical-mobile failures, and makes the repository and test suite read as intentional current software.

The implementation is organized as independently reviewable workstreams, but they share one release contract and one final gate. This avoids two failure modes:

- a loose backlog of unrelated patches with no coherent completion condition;
- a monolithic qualification ceremony in which every change triggers every historical check.

## Chosen approach and rejected alternatives

### Chosen: one release with explicit system boundaries

Use one `2.2.0` design and plan with separate boundaries for the Egregore identity migration, content grounding, model storage, mobile layout, mobile runtime stability, dock rendering performance, repository hygiene, and release operations. Each boundary receives the smallest test and qualification that can prove its public contract.

### Chosen: one atomic active-namespace migration

Rename the complete maintained product contract after obsolete tests and documents are removed, but before formatter, linter, profile, cache, mobile, and performance implementation. Current UI, system prompt, accessibility, metadata, legal copy, source namespace, qualification seams, tests, and active documentation move together. Keep `/chatbot/` and generic `/assistant/` routes stable, and redirect the only public name-bearing legacy route, `/licenses/jets-ghost/`, permanently to `/licenses/egregore/`.

### Rejected: frontend-only rename

A presentation-only change would leave the model identifying itself as Jet's Ghost and would split visible copy from live regions, errors, structured data, legal material, tests, and maintained code. That is not a coherent product identity.

### Rejected: permanent display-name alias

Retaining `JetsGhost*`, `JETS_GHOST_*`, branded paths, and qualification commands behind an `Egregore` display constant would reduce the first diff but preserve two product names indefinitely. The rename happens before new cache keys and 2.2 features so the maintained namespace can move once without a visitor-data migration.

### Rejected: split maintenance into `2.1.1` and defer capability work

The physical-mobile layout defects could be patched independently, but the approved scope now includes a new assistant capability, model caching, tooling, and repository cleanup. Splitting the work would duplicate release coordination while leaving the current documentation and test ownership ambiguous.

An urgent independently verified production defect may still justify a patch before `2.2.0`, but the current plan does not assume one.

### Rejected: preserve the completed `2.0.0` and `2.1.0` plans as active authorities

Those documents contain durable historical reasoning but also contain completed containment steps, superseded route states, paired real-model ceremony, and the instruction that caused the missing GitHub Release. They will be archived as release history after their still-current constraints are carried into this design and `AGENTS.md`.

## Goals

1. Rename the maintained local assistant to Egregore across its complete active product and code contract while preserving stable generic routes and accurate historical evidence.
2. Make `/about/` the single canonical source for Jet's public profile and make that source available to Egregore with normal provenance and citations.
3. Persist the exact pinned model in Cache API after explicit activation, without time-based expiry or a second storage subsystem.
4. Correct the confirmed Xiaomi 14T layout defects and obtain enough device evidence to make an honest runtime-support decision.
5. Audit visible Liquid Glass dock performance on the Xiaomi 14T and adopt a trace-supported optimization only if it preserves the approved visual and behavioral contract.
6. Make every retained test, fixture, script, document, and support path express a current public or operational contract.
7. Adopt Prettier and ESLint as separate, deterministic repository gates after obsolete test and documentation surfaces are removed.
8. Reconcile legal links, navigation ownership, contributor guidance, release records, SEO, Search Console follow-up, and versioning.
9. Release `2.2.0` through proportional qualification rather than repeating the complete `2.1.0` ceremony.

## Non-goals

- No retrieval redesign, retrieval benchmark programme, embedding model, reranker, PGlite, pgvector, EntityDB, or additional ranking strategy.
- No change from the deterministic MiniSearch rank-and-token-budget packer.
- No model change, E4B switching, hosted inference fallback, tool use, multimodality, or persistent conversation history.
- No CMS, Cloudflare, server adapter, Tailwind 4, Astro major-version, or broad dependency migration.
- No visual redesign of Egregore, the Liquid Glass dock, or the site identity; the approved ghost icon, animations, and genuinely descriptive ghost-themed language remain.
- No `/egregore/` product route, `/assistant/` artifact-route migration, model rename, or rewrite of Jet's Ghost `2.1.0` release and archived evidence.
- No device-specific visual downgrade, opaque dock fallback, reduced animation, or lower-quality model behavior introduced merely to pass a metric.
- No new heavyweight mobile performance job or approximately `2 GB` model download in routine or nightly CI.
- No test, script, snapshot, or CI gate whose purpose is to prove that the cleanup itself happened.
- No Git history rewrite, release-tag movement, or publication of user-owned `Untracked/` material.

## Durable architecture

### Site

- Astro 5 statically renders the site for Vercel.
- MDX and typed content collections own published material.
- React remains limited to stateful browser islands.
- `npm run build` remains pure and performs no external write.
- Public content requires `status === 'published'`.
- Egregore content additionally requires `assistant === true`.
- Canonical URLs, navigation, OpenGraph URLs, JSON-LD, and sitemap entries use the trailing-slash route contract.
- The shared document-title separator remains ` | ` through the canonical SEO formatter. Center dots used inside compact product copy are not document-title separators.
- The semantic OKLCH palette, Utopia type and spacing, `.text-link`, `.action`, and card recipes remain the design-system contract.

### Egregore

- `/chatbot/` remains the canonical indexed route; `/tools/chatbot/` remains a permanent legacy redirect and `/tools/` remains dormant and noindexed.
- One pinned Gemma 4 E2B LiteRT-LM model runs locally after explicit visitor consent.
- Compatibility checks do not import the runtime, fetch the corpus or model, create an engine, or allocate the GPU.
- The immutable eligible corpus, stable source identifiers, heading-aware segmentation, provenance, citations, and corpus versioning remain intact.
- One deterministic MiniSearch rank-and-pack pipeline owns context selection through the accepted one-to-two-million eligible-token design boundary.
- The assistant refers to Jet in the third person, does not speak on his behalf, answers only from supplied published sources, and abstains when evidence is absent.
- Only validated citations actually used in a response are exposed to visitors.
- Prompts and conversation state remain session-only and local to the browser.
- The fake runtime is permanent deterministic development and test architecture, not modernization residue. Audit its individual scenarios and instrumentation and remove only genuinely orphaned cases; preserve its lifecycle, failure, privacy, responsive, and interaction coverage. It must remain unavailable and absent from Production artifacts.

## Workstream: persistent pinned-model storage

Introduce one browser-owned model-source boundary between `LiteRtGemmaRuntime` and the pinned model URL. The boundary resolves either:

- a `ReadableStream<Uint8Array>` from the exact committed Cache API response; or
- the existing pinned URL for an explicit uncached attempt.

Use one versioned Cache Storage namespace whose identity includes the cache schema and exact model SHA-256. Use the pinned repository revision and filename in the request key. A model-version change produces a different identity and removes obsolete Egregore model cache namespaces; an application-version change does not.

On a cache hit, return the stored response body without a model-network request. On a miss:

1. fetch the exact pinned URL only after **Load Egregore**;
2. require the reviewed trusted-origin, redirect, status, and expected-length contract;
3. complete `cache.put()` without cloning or teeing the approximately `2 GB` body;
4. read the committed response back from Cache API;
5. pass that response body to LiteRT-LM.

If Cache API is unavailable during preflight, the visitor may explicitly continue with the existing uncached URL path. If a cache write fails after download begins, do not silently start a second approximately `2 GB` transfer; surface a recoverable state with an explicit uncached retry.

The cache is best-effort browser storage. It has no TTL, timestamps, expiry timer, service worker, IndexedDB, OPFS, background cleanup, or application-version invalidation. **Unload** releases only conversation, engine, runtime, GPU, and memory state. A separate **Remove downloaded model** action deletes the model cache and appears only when a current cached model exists.

Deterministic small-response tests own interrupted writes, quota failure, eviction-like recovery, and retry authorization. The real-model qualification covers one cold commit, one warm reuse with no model-network request, reload survival, Unload preservation, privacy, and explicit removal at the end. The unchanged pinned bytes do not justify model-sized fault injection or repeated independent hash downloads on every deployment.

## Workstream: physical-mobile layout and runtime stability

### Layout

Mobile browser chrome exposes the current failure, but it is not the architectural owner of the fix. The fixed dock overlays layout without reserving space, fresh immersive entry cannot discover its control through document scrolling, and the Egregore shell can enforce a `40rem` minimum while its body is clipped. Keep `svh` unless device evidence establishes a separate viewport-unit defect; instead make short visual viewports, dock state, and immersive scrolling explicit contracts.

#### Dock discovery and visibility

Dock discovery and mobile dock visibility are independent session state:

- A fresh ordinary mobile document starts with the dock open and the disclosure undiscovered. The existing qualifying first-document-scroll interaction marks it discovered and closes it.
- A fresh mobile immersive layout starts with the dock open and the disclosure immediately available. It must not require prior navigation or document scrolling that the immersive shell cannot perform.
- An explicit visitor choice of open or closed persists across Astro client navigation, full reload, and back/forward history in the same tab. A non-dock link must not reopen a dock the visitor closed.
- Desktop and tablet layouts at `48rem` and above always expose the dock and do not render the mobile disclosure. Crossing that breakpoint suspends rather than deletes the remembered mobile preference; returning below `48rem` restores it.
- A new tab session without retained session state returns to the fresh open state.

Persisting a closed state also establishes discovery; a structurally valid closed-but-undiscovered value normalizes to discovered and remains closed so the visitor can reopen it. Missing state uses the route-appropriate fresh default. Malformed or unsupported retained data uses the fresh open state and is replaced on the next explicit toggle. Only unavailable or unreadable session storage falls back to operable page-lifetime state.

Pass the existing `immersive` layout boundary from `BaseLayout` through the dock wrapper. Do not special-case `/chatbot/` or infer layout mode from a pathname. Read retained session state before the dock's first interactive render so the interface does not visibly restore itself after mount. Use the same below-`48rem` boundary in JavaScript and CSS; do not let `768px` satisfy both mobile JavaScript and desktop Tailwind behavior.

The disclosure retains its current appearance and remains a semantic button with accurate `aria-expanded` and `aria-controls`. A closed dock is inert, hidden from the accessibility tree, and removed from sequential focus. Closing returns focus to the disclosure when focus was operating within that interaction. The state contract must not add a second dock, route-specific control, or persistent user-profile setting.

#### Egregore clearance and compact mobile content

Define one shared BaseLayout/navigation exclusion-zone contract from rendered dock placement rather than the state breakpoint alone:

- below `48rem`, the bottom overlay envelope reaches the highest occupied edge of the dock or raised disclosure control, plus the fixed bottom offset, normal separation, and safe-area inset;
- from `48rem` to below `64rem`, the always-open bottom dock has no disclosure but still owns a bottom exclusion zone;
- at `64rem` and above, the dock moves to the top and the immersive header owns the corresponding top separation instead of a bottom reserve.

The fixed navigation and every internally scrolling Egregore lifecycle surface consume that same contract; do not duplicate dock-height guesses inside Egregore. Keep each applicable exclusion zone stable across open/closed transitions so toggling does not reflow Egregore and reopening cannot cover content.

Do not retain the current below-`370px` exception as the only activation protection. Primary activation, consent, loading, recovery, pre-conversation, conversation, composer, and disclosure content must remain reachable and must not render beneath the fixed navigation while it is visible. Hiding the dock is a visitor preference and performance affordance, not the workaround required to use Egregore.

Below `48rem`, the Egregore shell must fit the actual short viewport instead of allowing `min-height` to force clipped content behind a non-scrolling body. Qualification includes a fresh `375 × 680` or shorter measured-phone viewport with the dock visible, not only the taller emulated Pixel and `430 × 932` cases.

At small-mobile widths below `48rem`, do not render starter-prompt buttons. Direct composition remains the primary task. Tablet and desktop layouts retain the prompts where they fit naturally; no carousel, chip scroller, or alternate mobile interaction replaces them.

Keep the exact reliability disclosure **Egregore can make mistakes. Check cited sources.** immediately above the composer until the first submitted message. Use the existing Utopia `text-xs` tertiary/meta token on all viewports. The normal Xiaomi presentation should fit on one line, while zoom, enlarged text, localization, and constrained widths must wrap without clipping or horizontal overflow.

The composer, dock, header, loading hierarchy, and approved ghost animations retain their current visual treatment, motion language, and interaction semantics except for the explicit state and clearance corrections above.

### Runtime termination

The intermittent return from Chrome to the Android home screen is a separate process-level symptom. Screen mirroring can verify visible layout but cannot establish whether Android killed the renderer, Chrome crashed, the GPU process failed, or LiteRT exhausted a resource.

A USB-debugging evidence path is now established on the Xiaomi 14T. The `2026-07-18` baseline confirms Android 16, Chrome `150.0.7871.128`, a physical `1220 × 2712` display at density `520`, a current `60 Hz` presentation mode, and a `375` CSS-pixel page width at the observed browser scale. Available viewport height is dynamic under browser chrome and the software keyboard and must be captured in each tested state rather than frozen as a device constant.

The phone reported approximately `11.6 GB` total memory with approximately `3.8 GB` available during the probe. Android retained historical Chrome low-memory exits, but not an entry that can be correlated to the reported Jet's Ghost 2.1 termination. This supports memory pressure as a credible hypothesis, not a diagnosis. Do not make another real-model attempt until deterministic layout/state qualification, deterministic cache qualification, and the cool-device dock audit are complete. Begin a bounded ADB and Chrome evidence capture before that one cold activation and record only the minimum non-conversation facts needed to classify the termination. Do not repeatedly crash the device for benchmark completeness.

The release decision is evidence-based:

- if a contained runtime or lifecycle defect can be corrected without changing the pinned model or approved product behavior, fix it and require one bounded successful phone run;
- if the failure is a browser/platform limitation or cannot be corrected without reducing answer quality, changing the model, or manufacturing a misleading compatibility claim, stop and obtain Jet's explicit approval for the resulting supported-device boundary before release.

A fake-runtime responsive test can close the layout finding but cannot close the process-termination finding.

## Workstream: site-wide Liquid Glass dock performance

Treat mobile dock performance as site-wide pre-existing debt, not an Egregore or Grainient regression. This workstream is a bounded optimization audit, not a requirement to manufacture a performance patch. Measure it on a cool Xiaomi 14T before loading the model.

Use one static route for one decisive baseline comparison between visible and hidden dock states across idle, scroll, open, close, and post-transition intervals. Repeat only the decisive interval once on Home to confirm that Grainient does not change the result. Record frame presentation, dropped or partially presented frames, paint/composite work, layer behavior, and memory. If and only if that baseline isolates a material safe bottleneck, allow one narrow implementation-and-retrace cycle, then stop. Temporary traces and instrumentation remain local unless a compact artifact has an explicit continuing owner.

Only implement changes supported by the trace, beginning with filtered-area lifecycle, duplicate filtered surfaces, layer ownership, displacement-map regeneration, resize observation, and repaint scope. Preserve distortion, translucency, shadows, geometry, icons, theme response, the physical-mobile discovery and visibility contract, navigation, focus, reduced motion, and accessibility semantics.

Presentation near the device's current `60 Hz` ceiling remains the diagnostic aspiration: approximately `57` or more presented frames per second over a representative steady-state sample, no sustained visible jank, and no material hidden-state regression. If the device is deliberately tested in a higher-refresh mode, `60fps` remains the comparison ceiling; the higher refresh rate is not itself a requirement. This is a one-release investigation signal, not an automated acceptance floor or permanent benchmark.

Two outcomes are valid. If the trace identifies a meaningful fidelity-preserving optimization, implement it and remeasure. If the bounded evidence does not isolate or justify one, record that evidence-backed no-change conclusion and stop; do not claim that every possible optimization has been exhausted. Falling short of the diagnostic aspiration does not by itself block release or require a cosmetic concession. Jet's explicit decision is required only before making an actual visible or behavioral trade-off; never silently weaken the dock to improve a benchmark.

## Proportional qualification

Routine and nightly CI retain deterministic unit, content, documentation, formatting, lint, build, production-artifact, accessibility, and fake-runtime browser checks. They never download the real model.

The `2.2.0` candidate receives one combined production-equivalent real-model sequence because profile, corpus, prompt-facing behavior, and model delivery change:

1. cold activation commits the model cache;
2. ask **Who is Jet?**, **What does Jet do?**, one Timesheet/work-or-research question, and one unsupported private question, resetting between cases;
3. verify useful third-person grounding, About citation resolution, ordinary work citations, and unsupported abstention;
4. unload and perform one warm activation;
5. verify the warm path makes no model-network request and that cleanup/recovery remain credible;
6. unload again, explicitly remove the downloaded model, and verify that the current Egregore cache is gone.
