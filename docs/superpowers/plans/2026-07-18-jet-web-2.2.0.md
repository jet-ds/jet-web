# Jet Web 2.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task by task. Use `superpowers:test-driven-development` for product changes, `superpowers:systematic-debugging` for defects, and `superpowers:verification-before-completion` before any completion claim.

**Status:** Implementation in progress

**Goal:** Release `jet-web 2.2.0` with the maintained local assistant renamed atomically to Egregore, the static-site platform on the reviewed Astro 7/Tailwind CSS 4/TypeScript 6 matrix, canonical About-backed profile grounding, durable Cache API model reuse, corrected Xiaomi mobile and dock-state behavior, a bounded evidence-led Liquid Glass dock performance audit with any earned optimization, and a smaller intentional repository surface.

**Architecture:** Preserve the existing Astro static-site and local Gemma architecture. After historical cleanup, move the complete maintained assistant contract to one browser-safe Egregore identity and source namespace while retaining `/chatbot/` and generic `/assistant/` routes. Establish formatter and linter gates, bridge the existing JavaScript-owned Tailwind design system to Tailwind 4 under Astro 5, then move the Astro platform set before adding one typed `profile` content record, one model-artifact source boundary, and one explicit session-scoped mobile dock state. Add no retrieval, server, durable user-profile, or CI subsystem. Prove each change at its narrowest public boundary and finish with one proportional real-model sequence plus normal Production release and indexing operations.

**Tech stack:** Node.js 24.x, npm, Astro 7.1.3, MDX, React 19.2.7, TypeScript 6.0.3, Tailwind CSS 4.3.3 through `@tailwindcss/vite`, Utopia tokens, Vitest, Playwright, LiteRT-LM `0.14.0`, MiniSearch `7.2.0`, Cache API, Vercel, GitHub Actions, Chrome DevTools, and Android Debug Bridge.

**Design authority:** [Jet Web 2.2.0 Design](../specs/2026-07-18-jet-web-2.2.0-design.md)

**Execution checkpoint (2026-07-21):** Tasks 1 through 3 are complete on the implementation branch through the Egregore identity boundary. The remaining capability, mobile, performance, tooling, qualification, and release tasks are not complete, and no `2.2.0` deployment is implied.
