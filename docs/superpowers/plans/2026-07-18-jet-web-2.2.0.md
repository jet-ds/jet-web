# Jet Web 2.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task by task. Use `superpowers:test-driven-development` for product changes, `superpowers:systematic-debugging` for defects, and `superpowers:verification-before-completion` before any completion claim.

**Status:** Ready for implementation

**Goal:** Release `jet-web 2.2.0` with canonical About-backed profile grounding, durable Cache API model reuse, corrected Xiaomi mobile and dock-state behavior, a bounded evidence-led Liquid Glass dock performance audit with any earned optimization, and a smaller intentional repository surface.

**Architecture:** Preserve the existing Astro static-site and local Gemma architecture. Add one typed `profile` content record, one model-artifact source boundary, and one explicit session-scoped mobile dock state without adding a retrieval, server, durable user-profile, or CI subsystem. Prove each change at its narrowest public boundary and finish with one proportional real-model sequence plus normal Production release and indexing operations.

**Tech stack:** Node.js 24.x, npm, Astro 5, MDX, React 19, strict TypeScript, Tailwind CSS 3, Utopia tokens, Vitest, Playwright, LiteRT-LM `0.14.0`, MiniSearch `7.2.0`, Cache API, Vercel, GitHub Actions, Chrome DevTools, and Android Debug Bridge.

**Design authority:** [Jet Web 2.2.0 Design](../specs/2026-07-18-jet-web-2.2.0-design.md)

## Global Constraints

- Work from the canonical `/Users/jet/jet-web` folder. Do not create another durable repository folder or modernization worktree.
- Start from local commit `27afb67dc169d5fd725d6e78457e5ee84e66145e`, which already contains the published Timesheet work, unified Blog/Works/Home content cards, and their follow-up contract hardening.
- Preserve user-owned `Untracked/` content. Do not inspect, format, lint, move, publish, or make tests depend on it.
- Keep `package.json` at `2.1.0` until the final release task. The product reads its visible version dynamically from that package value.
- Follow the Contract-Coupling Principle in the design. Do not add a cleanup ledger, ratio gate, source-string proxy, annotation-name ban, snapshot, or CI job whose only purpose is to prove that cleanup happened.
- Keep real-model downloads outside routine and nightly CI. Use the fake runtime only as deterministic test infrastructure and verify that it is absent from Production output.
- Do not change retrieval strategy, model, visual identity, dock appearance, or support claims merely to force a green metric.
- Keep mobile dock discovery and explicit open/closed visibility as separate session-scoped state. Immersive layouts expose the disclosure immediately; navigation, reload, and history preserve the visitor's choice; tablet/desktop presentation suspends rather than deletes it.
- Use focused RED/GREEN tests for product changes, but delete or consolidate obsolete tests before introducing formatter and linter baselines.
- Keep external mutations ordered and reversible: the missing `v2.1.0` Release may be created from its existing tag; deployment, Search Console actions, the `v2.2.0` tag, and the `v2.2.0` Release happen only after the exact candidate passes its gates.
- Never use repository-wide staging in the shared worktree. Stage only individually reviewed task paths, then inspect `git diff --cached --name-status` and `git diff --cached --check` before each commit.
