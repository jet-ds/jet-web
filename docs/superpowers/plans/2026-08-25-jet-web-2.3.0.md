# Jet Web 2.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to execute this plan. When execution remains in the current task, use `superpowers:subagent-driven-development` where permitted. Every task must pass the implementation review loop below before its commit.

**Goal:** Deliver Jet Web `2.3.0`: coherent collection contracts and cards, search-first Blog discovery, chronological Works discovery, finite accessible Homepage depth carousels, finite `ItemList` schema, safe Egregore Markdown, usable long-form navigation, CSS-first Tailwind theme ownership, a current dependency graph, and a deliberately compacted durable test suite.

**Architecture:** Astro resolves all published content, ordering, display records, and structured-data membership on the server through one pure typed collection layer. Static Astro cards remain the complete no-JavaScript archive; small client enhancements own Blog search, Works filtering, the two Homepage Framer Motion carousels, and article contents behavior. Egregore gains a focused Markdown renderer without changing retrieval, citations, model loading, or local-only boundaries. CSS owns every utility-generating design token.

**Tech stack:** Node 24.x, npm, Astro 7, MDX, React 19, Framer Motion 12, Tailwind CSS 4 with `@tailwindcss/vite`, TypeScript 6, Vitest, Testing Library, Playwright, `react-markdown@10.1.0`, `remark-gfm@4.0.1`, and Vercel static hosting.

**Approved specification:** [`docs/superpowers/specs/2026-08-25-jet-web-2.3.0-design.md`](../specs/2026-08-25-jet-web-2.3.0-design.md)

## Per-task implementation review loop

Before every task commit:

1. Run the task's focused tests and its listed proportional browser/deployment gate, then run the complete deterministic `npm run verify` gate under Node 24 before committing.
2. Review the diff against the approved specification: check required behavior, progressive enhancement, accessibility, error handling, and explicit non-goals.
3. Review code and tests for clarity, type safety, duplication, browser-boundary justification, and durable-contract coupling.
4. Remove developmental tests, helpers, comments, or compatibility branches that are no longer needed.
5. Run:

   ```bash
   export PATH="/opt/homebrew/opt/node@24/bin:$PATH"
   npm run verify
   git diff --check
   git status --short
   ```

6. Stage only the task paths named in the task, then inspect:

   ```bash
   git diff --cached --name-status
   git diff --cached --check
   ```

7. Commit only when both reviews are clean. If either review finds a material issue, fix it and repeat the loop.
